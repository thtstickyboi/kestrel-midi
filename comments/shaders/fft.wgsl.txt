// Merlin M1': the batched complex FFT.
//
// One workgroup per transform, the whole transform resident in workgroup
// storage, ping-ponging between two halves of `buf`. Stockham rather than
// Cooley-Tukey because Stockham is *self-sorting*: the permutation is folded
// into the addressing, so there is no bit-reversal pass and no scratch buffer
// in global memory.
//
// Two properties matter more than speed here:
//
//   * **Fixed schedule.** Every stage reads and writes the same addresses on
//     every run. The development notes section 6 lists cuFFT plan selection as a
//     determinism risk precisely because a library may choose differently run
//     to run; there is nothing to choose here.
//   * **Table-driven twiddles.** They come from a host buffer computed in f64,
//     not from `cos`/`sin` in the shader. WGSL does not pin the precision of
//     those, so computing them here would make the output depend on the
//     driver's transcendental implementation -- fine run to run on one
//     machine, not fine as a claim about byte-identity.
//
// Radix 4, with one radix-2 stage first when log2(N) is odd. N = 2048 is 2^11,
// so it is one radix-2 stage followed by five radix-4 stages: six passes over
// workgroup storage rather than the eleven a pure radix-2 would take.
//
// Storage: 2*N complex f32. At N = 2048 that is 32,768 B against the 49,152 B
// this adapter reports. N = 4096 would need 65,536 and does not fit, which is
// the real reason the development notes section 5 starts at P = 2048.

// ---------------------------------------------------------------------------
// Real transforms.
//
// A 2N-point real DFT is an N-point complex one plus O(N) of fixup. Pack the
// reals as z[k] = x[2k] + i*x[2k+1] -- which is what `data` already is, so the
// pack is free -- transform, then split the result into the DFTs of the even
// and odd subsequences and recombine:
//
//     E[k] = (Z[k] + conj(Z[N-k])) / 2          even samples
//     O[k] = (Z[k] - conj(Z[N-k])) / (2i)       odd samples
//     X[k] = E[k] + W^k * O[k],  W = exp(-2*pi*i/(2N)),  k = 0..N
//
// with Z[N] taken as Z[0]. That is N+1 bins from N complex points, which is
// the whole reason the FDL stores `P+1` and not `P`.
//
// Both ends are exact rearrangements: there is no window, no approximation and
// nothing to tune.
// ---------------------------------------------------------------------------
