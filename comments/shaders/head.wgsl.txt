// Merlin: the head correction.
//
// The frequency-domain delay line plays `kernel_j[n] * r^(Dj-D)` for every n.
// That is the note only from `max(D, Dj)` on; before it the true note is the
// flat sustain `A[n]`, and the scaled kernel is too loud by `r^(-D)` -- 44% on
// an 8 ms note against a 0.25 s release, and 560x on a held second. Measured
// whole-file, that is a **-14 dB** null against the CPU reference, uniform
// across the render because every note carries it.
//
// So add the difference over `[0, D)`:
//
//     correction[n] = A[n] - kernel_j[n] * r^(Dj-D)
//                   = A[n] * (1 - f(n))
//
//     f(n) = 0            for n < skip      the delay line has not started yet
//            r^(Dj-D)     for skip <= n < Dj   the kernel is still sustaining
//            r^(n-D+1)    for Dj <= n < D   the kernel is releasing, the note is not
//
// `skip` is new and is what removes merlin's longest note. The delay line used
// to cache `kernel_j` whole, so its length was `Dj + tail` and grew with how
// long the note was held; a nine-second note wanted a thirteen-second kernel in
// every ring slot of every bus. It now caches from frame `skip = (Dj / P) * P`
// and fires the impulse `skip` frames late, which is the same convolution, and
// what it caches is the release tail alone. `f` being zero over `[0, skip)` is
// how this pass is told to supply the note itself there rather than a
// difference -- the same loop, the same cost, one more compare.
//
// The `+1` past `Dj` is the same convention `cpu.rs` uses: the envelope advances
// before the sample is scaled, so a kernel's first released frame already
// carries one factor of `r`.
//
// Two things follow, and both are why this is cheap.
//
// **`A[n]` is one buffer per waveform, not per entry.** The release bucket
// changes the envelope and nothing else, so every bucket of one waveform shares
// a head. The development notes section 3b's ten buckets per key cost one head between
// them.
//
// **`f` needs no `pow` in the loop.** It is constant at `r^(Dj-D)` until `Dj`
// and then multiplies by `r` once a frame. The host supplies the starting value
// so the shader never evaluates an exponential.
//
// ## Why integer atomics
//
// Heads overlap: on real material a note starts every few hundred frames and
// each correction runs for hundreds more, so many notes write one output frame.
// `../CLAUDE.md` bans float atomics for the mixdown because their ordering is
// not reproducible. Integer addition is associative and commutative, so this is
// bit-exact whatever order the invocations land in -- the same argument, and the
// same 32-bit fixed point, as the impulse scatter in `fdl.wgsl`.

    /// Added to `f` each frame, after the multiply by `r`.
    ///
    /// The envelope recurrence is affine, `f = f*r + a`, rather than the plain
    /// `f *= r` it used to be. Zero for an ordinary note, which is the release
    /// the geometric form was written for. **CC120 is what needs the other
    /// half**: All Sound Off damps a channel over a fixed 96-frame *linear*
    /// ramp, which `f *= r` cannot express from a start of zero however `r` is
    /// chosen, and `r = 1` with `a = 1/96` expresses exactly. One fused
    /// multiply-add instead of a multiply, and the two cases share every other
    /// field.

[10] shaders/head.wgsl:127
    /// Per-frame gain increments, for a channel whose volume moves while the
    /// note sounds.
    ///
    /// CC7 and CC11 are resolved at the note's own frame and then ride the
    /// note, which is right only while the channel holds still. One test file's
    /// track sends 26,734 CC7 messages against 2,397 note-ons -- eleven per
    /// note -- and freezing them there is worth **-0.91 dB against the CPU
    /// reference**, i.e. an error the size of the signal. The host ramps from
    /// the gain at the note-on to the gain at the note-off, so both ends are
    /// exact and the delay line's tail, which is fired at the note-off gain,
    /// meets the head without a step.

[11] shaders/head.wgsl:140
    /// The gain the delay line's impulse was actually fired at.
    ///
    /// **The correction only telescopes when both halves carry the same gain.**
    /// The output over a note's body is `A*(1-f)*G` from here plus `A*f*G` from
    /// the delay line, and that is `A*G` only while the two `G`s agree. They do
    /// not once the head follows a moving channel, so the identity has to be
    /// written out: this pass produces `A*(G(n) - f*G_imp)` and the delay line
    /// produces `A*f*G_imp`, which sum to `A*G(n)` for any `G(n)` at all.
    ///
    /// Getting this wrong is not subtle. `f` is section 3b's scalar and it
    /// *amplifies* -- up to 3.2x -- so a mismatched pair does not drift, it
    /// multiplies: the first version of the ramp measured **+12.8 dB** against
    /// the CPU reference on a one-note test, where freezing the gain entirely
    /// measured -8.
    ///
    /// Equal to `gain_l`/`gain_r` when nothing moves, which is the old
    /// `A*(1-f)*G` exactly.

        // Constant until Dj, then a single multiply a frame. No exponential.
        //
        // `n + 1 >= hold`, not `n >= hold`: `f` has to have gained its first
        // factor of `r` by the time `src` reaches `Dj`, so the multiply belongs
        // at the end of iteration `hold - 1`. One iteration late leaves `f`
        // uniformly too large by a factor of `r` across the whole head, which
        // holds the correction at about -60 dB and looks like a precision floor
        // rather than an index bug.
