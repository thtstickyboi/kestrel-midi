// Key-major merlin: one (key, filter) group's convolution, by overlap-add with
// a large FFT built the four-step way from merlin's batched one.
//
//     out = SUM_e  x_e (*) k_e
//
// where `k_e` is entry `e`'s kernel and `x_e` its impulse train in the group.
// The song is cut into blocks of `hop` frames and each block of each firing
// entry is transformed at `n >= hop + longest kernel - 1`, so the circular
// convolution is the linear one and nothing wraps.
//
// **Both channels in one complex signal.** A note's left and right impulses
// differ only in gain, and the kernel is one real waveform, so the train is
// packed as `left + i * right`: transforming that, multiplying by the real
// kernel's spectrum and transforming back gives `y_left + i * y_right`
// exactly, which halves every transform.
//
// **A stereo kernel fills the other half.** It is `K = k_left + i * k_right`,
// one transform for both sides of a sample, and the note wants `y_left =
// g_left (*) k_left`, `y_right = g_right (*) k_right`. Written with `m = (g_left
// + g_right) / 2` and `s = (g_left - g_right) / 2`, that is `y = m (*) K + s (*)
// conj(K)`, so the train is packed as `m + i * s`. A centred note has no `s`,
// and then this is the plain product; see `mac`.
//
// A pair with few impulses skips all of that: `direct` adds its kernel at each
// impulse, in the time domain, after the key's transforms.
//
// Nothing here uses an atomic. The scatter's targets are unique by
// construction (the host merges impulses that share a frame of an entry), the
// multiply-accumulate walks a block's entries in a fixed order, and the
// overlap-add adds a chunk's blocks in order into what earlier chunks left --
// so the result is a pure function of the input.
