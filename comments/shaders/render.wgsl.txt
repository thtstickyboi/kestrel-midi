[1] shaders/render.wgsl:1
// Pass 2 of 4: render.
//
// One invocation per voice. Each voice's state stays in registers for the whole
// block, so the sequential parts of the DSP (phase accumulation, envelope,
// filter memory) are never round-tripped through memory. Frames are processed
// in tiles of TILE; at the end of each tile the workgroup reduces its
// TILE * 2 channel lanes across all WG voices and adds the result into this
// workgroup's own slice of the partial buffer.
//
// Per-frame results go straight into workgroup storage, and **must not** be
// staged in a per-invocation array. An `array<f32, TILE>` in the function
// address space looks free and is not: the shader compiler spills it to local
// memory as soon as the frame loop stops being trivially unrollable, every
// write then costs a memory round trip, and the cost grows with TILE where
// workgroup storage does not. The README has the sweep.
//
// No atomics anywhere. Each workgroup owns its partial slice outright, and the
// in-workgroup reduction is a fixed-order tree, so two runs produce bitwise
// identical partials. Two renders of the same input must be byte-identical;
// that requirement is why there is no atomicAdd mixdown here.

// `log2` computed identically on the host and here. See `bank::log2_exact`: the
// exponent comes out by bit pattern, the mantissa out of a shared table with
// integer interpolation, and the only floating point left is a `u32`-to-`f32`
// conversion, a multiply by a power of two and one add -- all exactly
// specified. A GPU's own `log2` is an approximate instruction, and the error
// would integrate straight into the phase accumulator.
