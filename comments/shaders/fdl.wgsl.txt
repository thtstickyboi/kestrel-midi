// Merlin: the frequency-domain delay line.
//
// the development notes section 2 in one line:
//
//     out[n] = SUM_e ( d_e (*) w_e )[n]
//
// Notes sharing an entry differ only in start frame and gain, so they collapse
// into a sparse impulse train `d_e` and the entry contributes that train
// convolved with its waveform. Partition each waveform into K pieces of P
// frames, keep the partitions transformed, and a block costs
// `8L * entries firing in it` -- note count is gone from the cost model.
//
// Five entry points, in the order a block runs them:
//
//   scatter   impulses -> per-entry time-domain input, integer atomics
//   to_real   fixed point -> f32, and clear for the next block
//   (fft.wgsl r2c)
//   mac       ring[(t+k) % K] += H[e][k] * D[e]   -- this is the whole cost
//   emit      lift ring slot t into the C2R input, clear it
//   (fft.wgsl c2r)
//   overlap   add the previous block's tail, keep this block's
//
// ## Overlap-add, where the development notes section 5 says overlap-save
//
// Deliberate, and the reason is the cost model. Overlap-save wants the input
// buffer to hold `[x(t-1) | x(t)]`, so an entry that fired in the previous
// block must be *present* in this block's input even when it has no impulses
// now -- which puts it in the firing list, and the firing list is the one
// quantity the whole design is trying to keep small. Zero-padding instead
// costs one time-domain carry of P frames **per bus**, not per entry, because
// the carry lives on the far side of the multiply-accumulate where everything
// has already been summed. At 2 buses that is 16 KB against inflating a
// 473-entry firing list.
//
// The arithmetic is unchanged: a P-frame impulse block convolved with a
// P-frame partition is 2P-1 long and fits a 2P transform, so the circular
// convolution equals the linear one and nothing wraps.

// ---------------------------------------------------------------------------
// 1. Scatter.
//
// One invocation per impulse. Integer atomics, not float: `CLAUDE.md` bans
// float atomics for the mixdown because their ordering is not reproducible,
// and integer addition is associative and commutative so the result here is
// bit-exact whatever order the invocations land in. Two notes of the same
// entry starting on the same frame is ordinary in black MIDI, so the atomic is
// not decorative.
//
// Impulses go in `[0, P)` of a `2P` row; the upper half stays zero, which is
// the zero-padding the overlap-add needs.
// ---------------------------------------------------------------------------

[13] shaders/fdl.wgsl:200
// ---------------------------------------------------------------------------
// 3. The multiply-accumulate. Everything else in this file is bookkeeping.
//
//     ring[(t + k) % K][bin] += SUM_e H[e][k][bin] * D[e][bin]
//
// One invocation owns one `(bus, lag, bin)` and walks that bus's slice of the
// firing list. Three properties, all load-bearing:
//
//   * **No atomics.** Distinct `k` give distinct ring slots because `k < K`,
//     so every `(bus, slot, bin)` is written by exactly one invocation.
//   * **Fixed entry order.** The firing list is sorted, so the summation
//     order is a pure function of the input and the result is bit-identical
//     run to run. The development notes section 6 determinism risk 2.
//   * **Deepest kernel first, so the loop can stop.** Entries have their own
//     partition counts now. Sorted descending, the entries reaching lag `k`
//     are a prefix of the range, so the first row that does not reach it ends
//     the loop -- total iterations are `SUM_rows depth(row)`, the useful work,
//     rather than `rows * K`. Without that the ragged cache would cost the
//     deepest entry's iteration count on every row, which is the trade the
//     rectangular cache was making in bytes.
//
// The early exit before the ring update matters as much as the one inside the
// loop: `K` is now set by the bank's longest release, so most `(bus, lag)`
// pairs have nothing alive on them and would otherwise read and write the ring
// to add zero. At 256 buses that is 4.2 MB per lag per step.
//
// This is the pass M0 measured at 344 GB/s under CUDA. The kernel read is the
// traffic; `spec` is small and re-read once per lag, which is what the L2
// pinning there was buying and what wgpu gives up.
// ---------------------------------------------------------------------------
