//! The 31-EDO template (`--31edo`): how a file written for it is
//! played.
//!
//! 12 keys cannot hold 31 steps of the octave, so the template does not try.
//! A file carries **extended note keys, 0 to 255**, one step of the 31-step
//! scale each (`octave = key / 31`, `step = key % 31`), which is not MIDI --
//! a key is seven bits -- and which a reader that masks it, as Kestrel does
//! without this option, plays as the wrong note. The player turns each one into
//! an ordinary key on one of **three adjacent channels**, tuned a few tens of
//! cents apart by a MIDI Tuning Standard scale/octave message (`mts`), so that
//! the three channels together have a pitch class for every step. That is what
//! a synth is handed; this module is the player's half of it.
//!
//! Written from the account of a player's author, who sent it with their
//! player's source and a capture fixture compared against the editor's own output,
//! and checked against two real files:
//!
//! * A step is a `(key offset, lane)` pair, the table below. The lane picks the
//!   channel of the triplet, `output channel = triplet start + lane`, and the
//!   key is `offset + 12 * octave + 24 * (source channel - triplet start)`,
//!   clamped to 127. Within a triplet the three source channels are three
//!   registers two octaves apart, which all play on the same three output
//!   channels.
//! * The triplets are channels 1-3, 4-6, 7-9, 11-13 and 14-16 of a port.
//!   **Channel 10 is not remapped**, whatever its keys are: it is drums.
//! * Note-ons and note-offs map alike, from the source channel and key, so a
//!   note is ended by the event that began it whichever lane it went to.
//! * A controller, program change or pitch bend sent on a melodic source
//!   channel is **sent on all three channels of its triplet**, bends
//!   included -- the lanes carry the tuning and nothing is converted to a bend.
//!   A SysEx is not remapped.
//! * The three tuning messages are the player's, sent before the first note and
//!   again after a reset. A template file carries them in its setup track as
//!   well, and they are the same bytes, so they are read twice and say it
//!   twice; a file that lacks them still plays in tune.
//!
//! **It is for files that say so**: a key over 127 is how a file says it, and
//! `midi::uses_extended_keys` looks for one. The render does not turn this on
//! by itself.
