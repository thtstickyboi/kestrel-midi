//! Turning note-ons into impulses.
//!
//! This is the host side of the development notes section 2. A note stops being a voice
//! and becomes three numbers -- which cached waveform, which frame, how loud --
//! and the backend's cost stops depending on how many of them there are.
//!
//! Two jobs, and they are separate on purpose:
//!
//! * [`EntryTable`] interns `(region, variant, bend, release bucket)` into the
//!   dense entry ids the kernel cache is indexed by. This is where section 3b
//!   earns its keep: **duration is not in the key**, it is a gain.
//! * [`BlockPlan`] assembles one block's impulses into the three arrays
//!   `Fdl::encode_block` wants. Fiddlier than it looks, because the firing list
//!   is grouped by bus, ascending within each group, and the impulses index
//!   *rows of that list* rather than entry ids.
//!
//! Nothing here talks to the GPU or to the driver. It is the piece that decides
//! what the backend is asked to render, and it is worth being able to test that
//! without either.

/// What makes two notes share a cached **waveform**.
///
/// Deliberately *not* the region, and deliberately **without the filter**.
///
/// The reference bank is 128 velocity groups that are byte-identical apart
/// from `lovel`/`hivel`, all including the same 88-region keymap -- so key and
/// velocity select 22,528 different *regions* that between them play 88
/// samples. Keying on the region therefore multiplies the cache by 128 for
/// nothing, which is what the first real-material run measured: one new
/// waveform every 6.3 notes.
///
/// the development notes section 3(c) is the fix: velocity's amplitude folds into
/// the impulse gain, and its cutoff is an LTI filter that moves to a per-bus
/// biquad. So this hashes what the sample and the envelope are, by value, and
/// omits `b0/b1/a1/a2` and `RP_FILTER`.
///
/// **Why moving the filter off the note is sound**, since section 3(c)'s stated
/// reason is not quite the operative one. `cpu.rs` applies the filter to the
/// *enveloped* signal (`x = s * g`, then the biquad), so linearity does not let
/// the filter be pulled out of one note's envelope. What makes it work is that
/// each voice's input is zero before its own note-on, so a filter reset per
/// voice at onset and a single bus filter running continuously produce the same
/// output -- provided every note on the bus shares the coefficients, which is
/// what the bus *is*.

    /// Section 3b's collapse: `env(D) / env(Dj) * r^(Dj - D)`.
    ///
    /// Computed in f64, and signed both ways. `Dj < D` is the ordinary case and
    /// amplifies, because a kernel released earlier is quieter in the tail;
    /// `Dj > D` happens only for a note shorter than its region's attack, via
    /// [`Self::reference`], and attenuates.
    ///
    /// **`env_ratio` was missing until 2026-09-10, and it was merlin's loudest
    /// defect.** Writing the two out for `n` past both release points:
    ///
    /// ```text
    ///   truth[n]    = sample[n] * env(D)  * r^(n-D+1)
    ///   kernel_j[n] = sample[n] * env(Dj) * r^(n-Dj+1)
    /// ```
    ///
    /// so the ratio carries `env(D) / env(Dj)` as well as the exponential. For
    /// `D >= flat_from` both envelopes are the sustain level and the ratio is
    /// one, which is every note on a bank whose attack is a millisecond -- so
    /// the reference bank never showed it. For a note that ends inside its
    /// attack it is well below one, and leaving it out **plays the note out at
    /// the level it would have reached had it been held** rather than the level
    /// it actually got to. Measured against `cpu.rs` before the fix: **+10.4 dB
    /// on a 40-frame note** against a 188-frame attack.
    ///
    /// The energy is in the tail, not in `[D, Dj)`: that window is 148 frames
    /// against a release of 12,000. An earlier attempt corrected the window and
    /// left the scalar alone, and measured *worse* -- see the entry in TODO.
    ///
    /// Callers pass the ratio rather than the params because this type knows
    /// nothing about a bank; `MerlinSynth::plan_note` reads it from the same
    /// params table the kernel was rendered with, which is the one that has the
    /// controller variant applied.

    ///
    /// A note feeds two buses -- `filter * 2` for left and `+ 1` for right --
    /// so `buses` is twice the distinct filter count.
    ///
    /// **Bucketed, not scanned per bus.** The first version looped over buses
    /// and filtered the whole note list each time, which is fine at two buses
    /// and quadratic at the 256 that section 3(c)'s per-velocity biquads need:
    /// 256 passes over thousands of notes, every block. This sorts once
    /// instead.
    ///

    /// descending, because entries have their own kernel lengths: sorted that
    /// way the rows alive at lag `k` are a prefix of the bus's range, and the

    /// testing every row against every lag. The entry id is the tiebreak, so
    /// the order is still a total one fixed by the input.

    /// [`Self::build`] into `self`, reusing its buffers and `scratch`'s.
    ///
    /// **Sorts notes, not note-channels.** A note feeds a bus pair, and within
    /// one bus the order is (depth descending, entry, frame) -- the same for
    /// the left bus and the right. So the notes are sorted once, by
    /// (filter, depth descending, entry, frame), and each bus is that order
    /// with the notes that are silent on it skipped. That is half the items the
    /// sort used to take (81.1 M notes against 119.1 M note-channels over the
    /// 44.75 M-note test file), and it makes a filter's notes one contiguous
    /// run, which is what lets the output be written run by run in parallel.
    /// The key is packed into a `u64` -- a field is only as wide as `bounds`
    /// and the partition say it can be -- so the sort compares one integer
    /// where it compared a four-field tuple with a `Reverse` in it. A note that
    /// does not fit its bounds is marked as it is keyed and the step is built
    /// again by the unpacked path, so the bounds are a speed and never a
    /// limit.
    ///
    /// The order is the one the sort of note-channels produced: bus ascending,
    /// then depth descending, entry, frame. What neither version defines is the
    /// order of two impulses with the same bus, entry *and* frame, which differ
    /// only in gain and which an unstable sort may put either way round. That
    /// is harmless for the reason it always was -- they land in the same row
    /// and the scatter is integer-atomic (section 5), so their sum does not

    /// agree on everything else.
