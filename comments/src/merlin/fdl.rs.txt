[33] src/merlin/fdl.rs:675
        // Ordered **within each bus range**, which is what the MAC reads: it
        // walks `fired[lo..hi]` for one bus and never crosses the boundary. A
        // globally-ordered check would be wrong as soon as there is a second
        // bus, since bus 1 restarts at whatever entry it happens to hear first.
        //
        // The order is `(depth descending, entry ascending)`, and both halves
        // are load-bearing. Descending depth makes the entries alive at lag `k`
        // a **prefix** of the range, so the MAC breaks out at the first row too
        // shallow instead of testing all of them -- which is what keeps a
        // ragged cache from costing `rows * max_depth` iterations to do
        // `rows * own_depth` of work. Ascending entry inside a depth breaks the
        // tie, because the MAC sums in this order and an arbitrary tiebreak
        // would make the output depend on how the host happened to build the
        // list rather than on the input. See the development notes section 6.
