//! Building the cached waveforms the FDL convolves against.
//!
//! the development notes section 7: kernels come from **running the existing render
//! pass** with one voice. The point is not convenience -- it is that the two
//! backends then cannot disagree about what a note sounds like, because one is
//! defined in terms of the other. The null test stops testing the DSP and
//! starts testing the summation, which is the only thing Merlin actually
//! changes.
//!
//! ## One render per entry, not one per release bucket
//!
//! The obvious builder renders a note per `(region, key, velocity, release
//! bucket)`, issuing a note-off at each bucket's reference point `Dj`. That is
//! about ten renders per key for nothing, because section 3b's collapse says
//! what the release *is*:
//!
//! ```text
//! kernel_j[n] = sustain[n] * (1 for n < Dj, r^(n - Dj) for n >= Dj)
//! ```
//!
//! So render the voice **once with no note-off at all** and apply the release
//! on the host. Every bucket is then a multiply over the same buffer.
//!
//! **This is exact only while the amplitude envelope is flat at `Dj`**, which
//! is section 3b's stated premise and is why `ampeg_sustain=100` keeps
//! appearing in the development notes. If a region's decay is still running when
//! the note is released, the real synth releases from the level the decay
//! reached and stops decaying, while this multiplies a still-decaying curve --
//! two different envelopes. `Kernel::build` checks for that and refuses rather
//! than producing something that would null at some unhelpful -30 dB and leave
//! someone hunting the summation for it.

[14] src/merlin/kernel.rs:265
    /// The same kernel, but only `[from, from + len)` of it.
    ///
    /// **This is what the frequency-domain delay line actually caches**, and
    /// the reason it does is the whole of the variable-kernel-length fix.
    ///
    /// `kernel_j` is the sustaining waveform out to `Dj` and its release after
    /// that, so cached whole its length is `Dj + tail` -- it grows with how
    /// long the note was held, and a nine-second note would want a
    /// thirteen-second kernel in every one of the delay line's per-bus ring
    /// slots. Storing it from `from = (Dj / P) * P` instead drops the leading
    /// partitions, whose content the head correction already reconstructs: it
    /// covers `[0, max(D, Dj))` regardless, and needs only to be told that the
    /// delay line contributes nothing there.
    ///
    /// The impulse is delayed by the same `from` to compensate, which is exact
    /// because convolution is shift-invariant. What is left to cache is the
    /// release tail, whose length is a property of the **region** and not of
    /// the note -- so the ring depth stops depending on how long a note is held
    /// and there is no longest note any more.

    /// [`Kernel::segment`] and [`partition`] in one pass: the segment
    /// `[from, from + lags * p)` laid straight into `out` as `lags` partitions
    /// of `p` frames, each zero-padded to `2p`, which is the `lags * 2p` reals

    /// memory whose prior contents are unspecified -- which is what a mapped

    /// that memory is write-combined on some drivers and a read from it is slow.

/// The first frame at which a region's amplitude envelope has stopped moving.
///
/// Section 3b's analytic release is exact only from here on, so this is what
/// [`Kernel::at_release`] refuses below and what
/// `ReleaseBuckets::reference` clamps `Dj` up to.
///
/// An earlier version compared `sustain` against `decay_target` and could never
/// fire: `decay_target` is `max(sustain, env_floor)`, so the two are equal for
/// every region whose sustain clears the floor. What matters is not the levels
/// but the **rates**.
///
/// **And a second one started the decay from `attack_end`, which is not a
/// level.** `attack_end` is `1.0 + hold_frames * attack_rate` -- the hold phase
/// is expressed by moving the attack's *target*, not by a stage of its own --
/// so it is far above 1.0 for any region with a hold. `cpu.rs` sets
/// `level = 1.0` when the attack ends (see its `ENV_ATTACK` arm) and decays
/// from there, so dividing by `attack_end` invents
/// `ln(attack_end) / |ln(decay_coef)|` frames of decay that never happen.
///
/// It is not a rounding error. On one General MIDI bank, measured 2026-09-10,
/// the median param set claimed **8.27 s** to settle and the worst claimed
/// **442.8 s**, of which 227 s was this. `flat_from` sets `Dj` and `Dj` sizes
/// the accumulator ring, so the bank could not start at any sensible
/// `--merlin-filters` -- see `examples/merlin_flat.rs`, which is what found it.
///
/// Public so `examples/merlin_flat.rs` can measure it against a real bank
/// using this code rather than a copy of it.

/// The amplitude envelope of a **sustaining** note at frame `n`.
///
/// This is `cpu.rs`'s `ENV_ATTACK` / `ENV_DECAY` / `ENV_SUSTAIN` arms in closed
/// form, and it has to stay that: `env_at_matches_the_reference_envelope` in
/// `tests/merlin_kernel.rs` renders a DC sample through `CpuSynth` and asserts
/// the two agree frame for frame, because everything below turns on the two not
/// drifting apart.
///
/// Three things about the reference are easy to get wrong and are why this is
/// not two lines:
///
/// * **The envelope advances before the sample is scaled**, so frame `n` sees
///   the level after `n + 1` steps. An instant attack is therefore at full
///   level on frame 0.
/// * **`attack_end` is not a level.** It is `1.0 + hold_frames * attack_rate`
///   -- hold is expressed by moving the attack's target -- so the counter runs
///   *past* 1.0 during the hold and `cpu.rs` applies `level.min(1.0)`. The same
///   clamp is here.
/// * **The decay starts from exactly 1.0**, not from wherever the counter got
///   to. `cpu.rs` assigns `level = 1.0` on the crossing frame.
///
/// A region whose sustain is at or below the floor dies at the end of its decay
/// rather than sustaining, and this returns zero there -- which is what the
/// reference plays.

///
/// **This is the kernel's length, and it is per region.** `merlin_kernel_frames`
/// used to be one constant for every entry -- 88,064 frames, 1.83 s -- and the
/// reference bank's release runs 1.25 s on 54 keys, 1.95 to 3.0 s on 28 more
/// and 4.0 s on 6. So the long keys were cut at 46% of their tail, mid-decay,
/// which is exactly the "notes cut off abruptly" the first full render was
/// reported as having. Five separate records deferred this; it is the fix.
///
/// The level the release starts from is `sustain`, not 1.0: `Kernel::segment`

/// ends exactly where the per-voice backend's note would.
