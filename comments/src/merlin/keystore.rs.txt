//! The file split once by key: what lets merlin's per-key render stop reading
//! the MIDI file again for every key group.
//!
//! The pre-pass decodes every event already, so it files each note event as it
//! goes, on its worker, with no merging: a key's stream is its tracks' events,
//! each track's in order, about three bytes an event and identical repeats
//! folded to a count. A key group then reads only its own keys' chunks, which
//! nothing else touches, and merges them by tick.
//!
//! **One temporary file**, opened so Windows keeps it in the file cache and
//! writes it out only under memory pressure, and deleted on close. So it is
//! RAM while RAM is free and disk when it is not, one code path either way, and
//! neither the working set nor commit charge. It is written once and read once.
//! It is told how much of its disk to leave free, is not begun if the file
//! looks too big for what is there, and stops if the disk fills as it goes. If
//! it cannot be written for that or any other reason, the store is dropped and
//! the parser falls back to reading the file a group at a time.
//!
//! **A stream in a chunk is segments**, one per track, each starting from a
//! zeroed `State`, so a chunk never needs the one before it.
