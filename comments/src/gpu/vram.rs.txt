//! How much video memory an adapter has, and how much of it is in use -- by
//! every process on it, not only this one.
//!
//! wgpu reports none of that. Its counters cover only what Kestrel allocated,
//! and although wgpu-hal asks DXGI and `VK_EXT_memory_budget` for budgets, it
//! keeps the answers to itself. Windows publishes the whole-adapter figures in
//! two places, both behind raw system calls: DXGI, for how much dedicated
//! memory the adapter has and the budget it gives this process, and the
//! performance counters Task Manager reads, for what every process together
//! is using.
//!
//! **The only module besides the GPU buffer mapping layer allowed `unsafe`**,
//! by the user's decision of 2026-09-12, and only for those calls. Every
//! `unsafe` block says what makes it sound. Other platforms have no
//! implementation yet and report nothing rather than a guess.
