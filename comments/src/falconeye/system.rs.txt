//! The administrator step: what only an administrator can read about the
//! GPU's crashes, read and nothing else.
//!
//! Part 4 of FalconEye, opt-in and separate, as decided 2026-09-26. The
//! machine report asks first, then runs `kestrel --force-cli falconeye-system
//! --out <dir>` through Windows' own permission prompt
//! ([`super::winsys::run_elevated`]). That process only reads:
//!
//! - `%SystemRoot%\LiveKernelReports`, where Windows keeps a dump of each GPU
//!   reset (`WATCHDOG`) and other live kernel events;
//! - `%SystemRoot%\Minidump`, the blue screens;
//! - Windows Error Reporting's archive and queue under `%ProgramData%`: the
//!   short `Report.wer` texts for GPU resets and for kestrel.exe's crashes.
//!
//! **The dumps are listed, not copied**: name, size, date. They hold raw
//! kernel memory, which may hold anything, and nothing can check it for
//! personal data. The dates alone say when the GPU was reset. The `.wer`
//! texts are copied with names hidden.
//!
//! **It never** runs a render elevated, or changes a setting: not
//! `TdrDelay`, and not `LocalDumps`, which would make Windows keep full dumps
//! of kestrel.exe. Both are the user's to set, and the report says how.
