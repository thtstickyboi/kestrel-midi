//! What FalconEye reads on Linux and macOS, added in 1.2.3: how a render that
//! went without a word died, the system's own records of the GPU, and the
//! machine report's operating-system section.
//!
//! Windows gets these from a dead render's exit code and its event logs
//! (`winsys`, `watch::windows_events`). Here the watcher cannot read the exit
//! code at all: the render is its parent, not its child, and only a parent
//! may. So it reads what the system wrote down instead:
//!
//! - **Linux:** systemd's record of the crash (`coredumpctl`), where systemd
//!   catches core dumps, and the kernel log -- a segfault line naming the
//!   module, the out-of-memory killer, and the GPU drivers' own errors
//!   (NVIDIA's Xid, amdgpu's ring timeouts and resets, i915's hangs).
//! - **macOS:** the crash report Apple writes to
//!   `~/Library/Logs/DiagnosticReports`, and `log show`.
//!
//! **All of it is files and the system's own tools; there is no `unsafe`.**
//! The parsers are plain text in, text out, and compiled everywhere so their
//! tests run on every platform; only the reading is per platform. None of
//! this has run on a real Linux or macOS machine by the time of writing
//! (2026-09-27): it was built and tested on Windows, and checked to compile
//! for both.
