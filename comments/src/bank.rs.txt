[28] src/bank.rs:433
/// `log2` computed identically on the host and on the device.
///
/// **Not a micro-optimisation, and the reason is worth stating.** A GPU's
/// `log2` is an approximate instruction -- NVIDIA's is good to about 2^-22
/// *relative to its result*, so `log2(0.001)` carries ten times the absolute
/// error of `log2(1.5)` -- and the host's is correctly rounded. Anywhere that
/// difference reaches a phase step it integrates, because the modulation
/// envelope's offset ramps up and then **holds**, unlike an LFO's, which
/// changes sign twice a cycle and cancels itself out.
///
/// A finer grid was tried first and passed the null test with four decibels
/// to spare, which is not the same as fixing it -- the drift was still there,
/// merely slower. This removes the *class* of defect: the exponent comes out
/// by bit pattern, the mantissa is read from a shared table with integer
/// interpolation, and the only floating point left is an exactly specified
/// `u32`-to-`f32` conversion, a multiply by a power of two and one add. Two
/// backends given the same input return the same bits. The drift figures are
/// in the development notes.
///
/// The table is coarse on purpose -- linear interpolation over a 1024th of the
/// mantissa leaves about 1.7e-7 of error, more than a correctly rounded `log2`
/// would -- and that costs nothing, because it is the *same* error on both
/// sides and amounts to 2e-5 of a cent at the largest pitch depth the format
/// allows.

/// Round to a multiple of 2^-22, through an integer.
///
/// The point is not the precision -- it is a hundred times finer than the
/// pitch grid downstream -- but that the conversion to an integer forces the
/// multiply feeding it to be *rounded*. Without that, an expression like
/// `1.0 - frames * rate` is a multiply next to an add, which a shader compiler
/// contracts into a fused multiply-add and the host compiler does not, and the
/// two backends then disagree by an ulp. An ulp is normally nothing; here it
/// reaches a phase step, and the modulation envelope's offset persists rather
/// than oscillating, so it integrates. The way back out is a multiply by a
/// power of two, which is exact, and the add that follows is exact too because
/// both operands are multiples of 2^-22 no larger than one.
///
/// Every arithmetic step in this function is exactly specified in both
/// languages, including the truncation toward zero that `as i32` and WGSL's
/// `i32()` share.

///

///
