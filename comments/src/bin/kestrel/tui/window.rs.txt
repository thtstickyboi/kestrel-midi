//! Windows of their own: how Extras and Merlin open one, and how a window
//! hands over to another and goes.
//!
//! **Opening.** A new terminal window running this executable with a flag. On
//! Windows it goes through `start`, not by spawning the child into a new
//! console: the standard library always hands a child this process's standard
//! handles, so a child spawned straight into a new console gets the window but
//! reads its keys from this one, where the main menu is already waiting on
//! them. That shipped, and Extras could not be typed into (reported
//! 2026-09-12). `start` gives the process in the new window that window's own
//! input and output.
//!
//! **Closing the window a person came from.** Extras is a window of its own,
//! and so Merlin, started from it, has two windows behind it: Extras, which
//! just exits, and the main one, which is another process waiting for a line.
//! Killing it would leave its tab open on "process exited with code 1", so it
//! is asked instead, through a file: the window that wants it gone makes
//! `kestrel-quit-<pid>` in the temporary folder, and the guided renderer's
//! watcher thread (`serve_quit`) answers by removing the file and exiting
//! with 0, which closes the tab. A render under way refuses, by renaming the
//! file `.refused`, since what is on the screen is not for the person who
//! asked to throw away. A window that does not answer in time (an older
//! Kestrel, a process that is gone) is left as it is.
