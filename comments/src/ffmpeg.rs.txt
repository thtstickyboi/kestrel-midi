//! Locating ffmpeg, and encoding a render through it.
//!
//! `-o mix.opus` needs no flags: the extension picks the container, `PRESETS`
//! picks the settings, and the search below picks the binary. `--ffmpeg` is an
//! override for the case where ffmpeg is not on `PATH`, never a requirement.
//!
//! Everything a render needs from this module is resolved *before* the
//! soundfont load, because that is nine seconds on a real library and a
//! misconfigured encode should not cost it. Specified in
//! the development notes.
//!
//! Precedence, highest first:
//!
//! 1. an explicit path, from `--ffmpeg`
//! 2. the `FFMPEG` environment variable
//! 3. `ffmpeg` beside the Kestrel executable, or in an `ffmpeg/` directory
//!    under it -- where a future `get-ffmpeg` would put it
//! 4. `ffmpeg` on `PATH`
//!
//! **A candidate named explicitly is never silently skipped.** If `--ffmpeg`
//! or `FFMPEG` points at something that is not a working ffmpeg, that is an
//! error naming it, not a quiet fall through to `PATH`. Falling through would
//! mean a typo in `FFMPEG` renders with a different binary than the one asked
//! for and never says so, which is the failure mode `CLAUDE.md` forbids.

    /// Whether the codec reconstructs something other than what it was given.
    ///
    /// This decides the default limiter ceiling, and it is not cosmetic. A
    /// lossy decoder does not preserve peak level: encode a mix limited to
    /// exactly 0 dBFS and it decodes *above* full scale, which clips in any
    /// player with an integer output stage. Measured 2026-09-02 on a 429 s
    /// render whose WAV peaks at exactly 1.000000 with no samples over:
    ///
    /// | container | decoded peak | samples over |
    /// |---|---|---|
    /// | opus | +0.99 dBFS | 2,335 |
    /// | ogg  | +0.34 dBFS | 1,596 |
    /// | m4a  | +0.10 dBFS | 3 |
    /// | mp3  | +0.05 dBFS | 467 |
    /// | flac | 0.00 dBFS  | 0 |
    ///
    /// So every lossy container needs headroom and FLAC needs none.

/// Default brickwall ceiling for a lossy container, in dBFS.
///
/// -1 dBTP is the usual delivery recommendation, and it is *just* enough here:
/// at -1 the worst case above (opus) decodes to -0.07 dBFS with zero samples
/// over, so this material uses 0.93 dB of the 1 dB. -1.5 leaves 0.47 dB spare
/// and -2 leaves 0.90. If a future file still clips at -1, that margin is why,
/// and the fix is a lower ceiling rather than a different codec.
